Four layers of checks

From isolated modules up to a full pipeline run with real files.

{% include number.html value=L.unit.tests %}
Unit tests

Check each module in isolation, such as WAV header parsing or kit naming.

{% include number.html value=L.integration.tests %}
Integration tests

Exercise the modules together against a real SQLite database and real files{% if L.integration.platforms.size > 0 %}, on {% include platforms.html list=L.integration.platforms %}{% endif %}.

{% include number.html value=L.e2e.tests %}
End-to-end tests

Drive the built app through its interface, the way a user would{% if L.e2e.platforms.size > 0 %}, on {% include platforms.html list=L.e2e.platforms %}{% endif %}.

Full-pipeline validation

Downloads Squarp's factory library{% if L.rehearsal.kits > 0 %} ({% include number.html value=L.rehearsal.kits %} kits, {% include number.html value=L.rehearsal.samples %} samples){% endif %}, builds a kit, writes a card, and checks that {% if L.rehearsal.cardFiles > 0 %}all {% include number.html value=L.rehearsal.cardFiles %} files{% else %}every file{% endif %} on it are exactly what they should be, byte for byte{% if L.rehearsal.platforms.size > 0 %}, on {% include platforms.html list=L.rehearsal.platforms %}{% endif %}.

Is my card safe?

  • Every file written to the card in full-pipeline validation is compared with what it should be, byte for byte.
  • The Rample's own settings folder on the card is never touched.
  • Any unexpected error or warning in the app fails the checks.
